# 全部脚本的本地持久化

## 保存内容

| 脚本 | 扫描结果 | 用户选择与偏好 |
| --- | --- | --- |
| Amex | 原有逐卡 Offer、状态、扫描时间继续保存 | 卡片、白名单、卡片优先级继续保存；新增搜索和面板折叠 |
| Citi | 按卡片保存规范化 Offer、登记状态及最后完整扫描时间 | 卡片列表、勾选、搜索、折叠 |
| Chase | 按卡片保存规范化 Offer、状态及最后完整扫描时间 | 卡片列表、勾选、搜索、折叠 |
| BankAmeriDeals | 优惠展示字段、资格和激活核验结果、扫描时间 | 当前 profile 确认、折叠 |
| US Bank | 优惠展示字段、激活核验状态、扫描时间 | 优惠勾选、搜索、折叠 |
| Wells Fargo | 优惠展示字段、激活状态、扫描时间 | 账户级激活确认、搜索、折叠 |

刷新和重新打开先展示缓存，不自动扫描、添加、续期或重试。取消选择不会清空已有结果；卡片重新检测保留仍有效的选择，US Bank 重新扫描保留同客户仍可激活的勾选。空列表的成功扫描会替换旧结果；失败扫描保留旧结果和时间，Citi/Chase 已成功扫描的卡片可独立保存。

## 会话与写入边界

- 新恢复的五个银行 workspace 都是待核验缓存。Citi 可以在一次手动添加操作中完成核验并继续；其他四个银行必须先手动扫描。Amex 延续既有缓存使用规则和未确认状态保护。
- Citi 恢复后可选择 **Add saved offers**：核对当前登录卡片后直接尝试缓存中可用的项目，不重新扫描优惠；或选择 **Refresh & add offers**：刷新全部卡片和优惠后直接添加已选卡上的可用项目。未确认记录必须走后者先核验；不自动重放。新卡默认不选，已选卡消失时停止并要求检查选择。Chase 需要原网页先捕获当前会话并核对客户与卡片。
- US Bank 保存客户标识的 SHA-256 指纹，切换客户清除旧选择。同客户的 token 轮换不抹掉选择。
- BankAmeriDeals 和 Wells Fargo 不假设未验证的稳定客户 ID，保存当前 token/激活地址的 SHA-256 指纹。重新扫描发现指纹变化，清除旧账户确认；即使是同一账户重新登录，也可能需要再次确认。
- 原始 Cookie、token、请求头、US Bank serving token、完整响应、地理位置都不写入 workspace。指纹仅用于比较，不能拿来认证。
- 发送激活请求前先保存未确认检查点。刷新、关闭或异常中断后，不能把该请求恢复成可直接重发；成功确认后立即更新快照。保存失败显示错误并阻止后续请求。
- 保存的是显示字段和用户偏好，不保存正在运行的队列、锁或自动恢复命令。银行返回的实时结果决定能否继续。

## 存储与升级

五个 workspace 使用各自的 `${script-id}:workspace`。工作流模板引入后，结果从 schema 1 显式前向迁移至 `schemaVersion: 2`，增加 `workflowType`；读取时保留旧值，下一次明确保存才写入新格式。它们复用小型共享读写/验证模块，每个银行声明自己的字段白名单，不直接序列化整个 state。

原有 `${script-id}:pacing` schema 1 完整保留，不更改等待/冷却期限。旧版没有 workspace 时按首次使用处理，第一次手动操作才创建结果快照，不触发网络迁移。Amex 既有卡片 schema 1 → 2 迁移不变；优惠结果另从 schema 1 → 2，加入 `amex-combination` 标记；`${script-id}:view` schema 1 继续保存视图偏好。详见 [工作流模板](workflow-templates.md)。

未来或损坏的 schema 保留原始值并提示错误，不用空快照覆盖。今后更改 workspace schema 必须添加显式前向迁移。

## 验证与待现场验证

单元回归覆盖结果/选择恢复、无启动请求、旧 pacing 兼容、未知/损坏 schema、存储失败、失败刷新、未确认请求和账户变化。Chromium 使用合成页面与全网络拦截，执行真实 document reload，验证结果、勾选、搜索和折叠恢复及手动重新扫描。

尚未在真实银行账户验证 Tampermonkey 存储、登录轮换与当前站点行为。离线回归和浏览器合成测试不等于真实网站操作成功。

Amex 卡片选择只从插件的 GM 快照恢复；不再读取或导入网站 localStorage 中的旧白名单。
