# Citi：默认全选与逐条继续

## 当前操作

首次点击 **Load cards & offers** 读取全部卡片和优惠，默认全选，不自动添加。页面加载和缓存恢复本身不发请求。

- **Add saved offers (N)**：先核对当前登录卡片归属，再处理已选卡中缓存为 `AVAILABLE` 的优惠。不会逐卡刷新优惠。已添加、未确认和冲突记录都跳过，搜索只影响展示。
- **Refresh & add offers**：刷新所有当前卡的优惠，再添加选中卡的可用优惠。新发现的卡默认勾选，已有手动取消的选择保留；未选卡只读取优惠。
- **Stop**：等待当前请求返回并保存结果，然后停止发出后续请求。添加阶段停止后可点 Add saved offers 继续剩余优惠；未确认项仍跳过。扫描阶段没完成则要求先完成刷新。

## 单条问题与整批失败

Citi 返回 HTTP 200 JSON，但没有明确登记成功时，记录该条 `UNCONFIRMED`，保存进度并继续下一条，不把它计入已添加，也不重发。已有未确认或冲突条目不再禁用整批缓存添加。UI 显示跳过原因和刷新核验入口；结束统计分别展示明确成功数量和未确认数量。

这直接覆盖一条未确认导致其余 225 条无法添加的情况。显式刷新后，如果银行已将该条标为已添加，就继续跳过；只有重新读取为可用时，才会进入这次用户主动刷新并添加的队列。

HTTP 错误、429、网络失败、超时、非 JSON、登录不匹配、存储失败和扫描未完成仍停止。429 按银行要求冷却；全局失败标记会保存，重载不能清除。仍然串行、按响应完成计时、没有自动重试或自动恢复。当前调速参数见 [自动调速](adaptive-pacing.md)。

## 选择和旧数据迁移

Citi 和 Chase 首次默认选中全部卡，新发现卡片默认勾选。手动取消，包括全部取消，跨刷新和重新检测保留。Chase 仍只读取优惠，不新增未验证的登记接口。

通用 workspace 升到 schema 3，保留原存储键、卡片、优惠、时间戳和显示偏好。schema 1/2 没有标记区分初始空选择与用户主动全不选，因此旧版空选择一次性迁移成全选；已有非空选择按原样保留。schema 3 明确保存初始化标记，之后的主动全不选不会再被重新勾选。读取只在内存迁移，下次明确保存才写入新格式。Amex 独立优惠快照仍为 schema 2。

## 验证与待现场验证

单元测试覆盖默认选卡、旧空选择迁移、保留手动取消、新卡勾选、不同登录阻止登记、单条未确认后继续、HTTP 失败跨重载保留、Stop 后恢复、缓存与刷新两条路径，以及损坏数据不覆盖。

真实 Chromium 合成回归覆盖按钮和选择状态、逐条请求、默认全选、无自动请求和不重复提交。可执行 Gherkin 包含“一条未确认 + 剩余 225 条”在 Stop、重载和继续后的完整场景。
