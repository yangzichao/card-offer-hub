# Citi：使用缓存添加，或刷新并添加

## 当前操作

首次使用点击 **Load cards & offers** 读取所有卡及优惠，随后明确选择卡片。不会自动勾选新卡，也不会在页面加载时请求或添加。

选卡后，界面只保留两种日常操作：

- **Add saved offers (N)**：直接使用已保存的优惠列表，仅添加所选卡片中标为 `AVAILABLE` 的项目。先读取当前登录卡片列表核对归属，但不读取逐卡优惠、不替换缓存列表、不改变最后刷新时间。缓存里已添加的优惠跳过；搜索不缩小添加范围。
- **Refresh & add offers**：同一次点击检测当前卡片、刷新所有卡的优惠（包括未选卡），完整刷新成功后直接添加已选卡上的可用优惠。不会再重复扫描，也不要求第二次点击添加。即使缓存里没有可添加优惠，这个入口仍可用。

正常状态只显示按钮、优惠数量和最后刷新时间，不重复解释“结果已恢复、可以继续、刷新可选”。没有保存结果、没有选择、冷却或结果待核验时才说明下一步。停止仅在任务执行时显示。

## 范围与失败处理

两种添加操作都核对本次点击时的选择；任一已选卡片不在当前登录卡片列表中就停止。新卡保持未选中，未选卡只参与全量读取，不参与添加。同一优惠在不同卡上各自处理，没有跨卡去重或优先级。

缓存路径有意不检查优惠的最新状态，可能遇到已经在网站添加或已经失效的项目。此时仍只接受原有明确成功信号；失败、HTTP 错误或未确认响应停止队列，不悄悄切换到刷新、不自动重试。已有未确认或冲突记录时，禁用缓存添加，改用 **Refresh & add offers** 先读取银行状态。银行已经确认添加的项目跳过；刷新后仍可用的项目由这次明确点击继续处理。

全量刷新失败或被停止时，不进入添加阶段。已读取的结果逐卡保存，其余卡片旧结果和最后完整刷新时间保留。存储失败阻止后续请求；请求前持久化未确认标记，避免刷新页面后直接重发正在处理的请求。Stop 等待已发出的请求落定并记录结果，然后停止后续请求。

缓存添加被手动停止时，如果尚未发送下一笔请求，或正在发送的请求已明确确认成功，**Add saved offers** 保持可继续，下一次点击重新核对登录后只处理剩余项目。等待请求间隔时停止不会把尚未发送的优惠误存成未确认。真实失败或未确认响应仍阻止继续，必须显式刷新；全量刷新被停止也仍要求完成刷新。

按钮上的数量只表示缓存里标为可用的优惠数量，不表示所有前置条件已满足。禁用原因分别显示：未确认结果数量、冲突状态数量、首次刷新未完成、后续刷新未完成或上次操作失败，避免有可用数量却只给出笼统的刷新提示。

沿用 workspace schema 2 与 `per-card` 标记，无新增存储格式。已有 schema 1 仍由公共迁移兼容。500 毫秒响应完成后间隔、同源标签页互斥、429 冷却与无自动重试保持不变。
