# 实测与调试日志

从 1.5.1 起，六家银行面板都可以下载自动调速日志。

1. 在 Tampermonkey 更新 Card Offer Hub，刷新银行页面，确认面板显示 1.5.1 或更高版本。
2. 照常选择卡片或账户范围，手动开始扫描或添加。遇到异常时保留当前状态，不需要反复点击重试。
3. 展开面板底部 **Automatic request speed**，点击 **Save debug log**。
4. 将下载的 `card-offer-hub-<bank>-<timestamp>.json` 发到调试对话，同时说明银行、点击了哪个按钮、预期结果和实际现象。可附面板错误提示截图，并遮住卡片信息。

日志自动保留在本机 Tampermonkey 存储中，按银行隔离，最多保留最近 200 条事件。页面刷新后仍可导出已保存的记录；长任务会淘汰较早记录，因此出问题后及时下载。下载不发起银行请求，也不上传日志。

导出包含：脚本版本、导出时间、当前调速参数、成功样本数、有效观察时长、等待与冷却期限，以及请求槽开始/结束、响应 HTTP 状态、结果分类、耗时、调速前后间隔和限流事件。请求槽耗时包含请求准备、网络、响应正文读取和验证；没有响应时不虚构 HTTP 状态。每条新事件也记录产生它的脚本版本。

日志使用字段白名单，不导出账户标识、卡号、卡名、优惠内容、URL、请求头、Cookie、token、请求/响应正文或原始错误文字。页面现有的 Amex Activity 含卡片和优惠名称，不会复制进调试文件。需要定位业务提示时，另提供遮盖账户信息后的面板截图。

日志快照 schema 为 1，保存在 `<issuer-script-id>:pacing:diagnostics`；与控制请求安全的 pacing 快照分开。日志保存失败会在速度详情里提示，当前页记录仍可下载；此时请在刷新前下载。限流策略本身保存失败仍会阻止后续请求。未知日志版本保留原样，不覆盖。

## 本地验证与待现场验证

离线测试覆盖日志上限、重载恢复、敏感字段排除、未知版本、日志存储失败与 pacing 存储失败，以及 Citi/Amex 两条传输路径的 429 事件顺序。Chromium 回归实际下载 JSON 并读取内容，验证刷新后保留限流记录，且导出不发送银行请求。

1.5.1 本地检查：`npm run build` PASS；`npm run check` PASS；`npm test` PASS（384 项）；`npm run test:browser` PASS（15 组浏览器回归，另含 11 个 Gherkin 场景、106 个步骤）。浏览器通过 `PLAYWRIGHT_MODULE_PATH` 指定本机可用的 Playwright 运行时。

待现场验证：真实银行会话的表现、Tampermonkey 存储和下载提示。合成测试不代表已经验证银行真实限额。
