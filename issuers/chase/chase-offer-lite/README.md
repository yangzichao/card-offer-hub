# Chase Offer Lite

本银行功能随 [Card Offer Hub 统一安装包](../../../bundles/all/README.md) 发布。

Chase Offers 的 Tampermonkey 脚本，提供与 Citi 一致的加载、缓存继续和刷新添加入口。按所选卡片逐条发送 Chase 的点击添加请求，重新读取对应优惠的 `ACTIVATED` 状态后才报告成功。

## 安装与使用

构建产物为 [`dist/card-offer-hub-all.user.js`](../../../dist/card-offer-hub-all.user.js)。首次发布前，在 Tampermonkey Dashboard → Utilities → Import from file 中导入本地文件；发布到 `main` 后可使用 [安装 / 更新链接](https://raw.githubusercontent.com/yangzichao/card-offer-hub/main/dist/card-offer-hub-all.user.js)，以后由 Tampermonkey 检查版本更新。

1. 安装后刷新 Chase 页面，登录并等待 Chase Offers 加载。如果首页没有加载预览，进入 Chase Offers，让 Chase 自身加载清单。
2. 首次点击 **Load cards & offers**，一次读取全部当前卡片与完整优惠，不添加优惠。卡片默认勾选，可以取消；主动取消的选择会保存，新发现的卡片默认勾选。卡片显示末四位便于区分。
3. **Add saved offers** 继续添加已保存的优惠。重开页面、停止或失败后，不必单独检测和扫描；这个按钮会先核对当前登录、读取所选卡的最新状态和点击参数，再添加原先保存且仍可用的优惠。不会把这次发现的新优惠纳入缓存添加，也不会重试之前结果未确认的优惠。
4. **Refresh & add offers** 重新读取全部卡片与优惠，再只给已选卡片添加可用优惠。未选卡片也刷新，新卡默认勾选；搜索只筛选显示，不改变添加范围。如果检测到不同客户，只加载新客户卡片，要求查看选择后再次手动添加。
5. 点击 **Stop** 后等待在途请求结束，保存进度。之后点击 **Add saved offers** 继续剩余项目；未确认的优惠会保留并跳过，读回明确已激活时才更新为成功。

首页的少量 Offer 预览只用于发现卡片，不当作完整扫描。刷新所有卡片中途失败或停止时，保留上一份完整结果。

页面加载时只安装被动观察器，不自动发请求。每次网络操作由上述按钮触发，同一时刻只有一个请求在途，从前一次响应完成起按已学习间隔等待，首次 1 秒、最低 0.5 秒，遇到限流减速并保存。面板最多显示 200 个搜索匹配项，读取清单没有此上限。

## 安全与状态

- 使用 Chase 当前浏览器登录会话，不复制抓包中的 Cookie、token 或账户标识，不向第三方发送账户数据。
- HTTP 错误、未知响应及未确认结果会停止流程，不自动重试。遇到 429 按 `Retry-After` 冷却，已有的更长冷却不会被覆盖。
- 存储使用带 schema 版本的结构。存储失败会显示错误并阻止新的操作。
- 卡片、勾选和 Offer 结果保存在本地。刷新先显示缓存；添加时核对 Chase 当前会话和卡片。不同客户不能使用旧缓存添加，显式刷新会加载新客户卡片并要求重新查看选择。
- 点击响应为空的 HTTP 200 只算已接收；必须重新读取同一卡同一 Offer 的 `ACTIVATED` 状态才算添加成功。点击所需参数只在当前页面内存中保留，刷新后由手动添加动作内部读取最新参数，不再要求额外点击扫描。

## 本地保存与恢复

扫描结果、已有选择、搜索条件和面板折叠状态保存在 Tampermonkey 本地存储，刷新或重新打开后恢复。页面显示最后完整扫描时间；恢复本身不发网络请求、不自动添加。取消勾选也会保存，不因刷新重新选中。

保存失败会显示错误；未知或损坏的快照保留原数据，不静默覆盖。快照只保存展示字段和选择，Cookie、登录 token、请求头、原始响应和地理位置不写入快照。正在添加时刷新，未确认的项目保留为未确认，后续手动添加时先核验，仍未确认的优惠保留并跳过。详见[持久化说明](../../../docs/local-persistence.md)。

自动调速的样本、间隔与冷却按银行保存，刷新页面不丢失，也不自动启动任务。速度详情默认折叠，无需用户调参。算法、缓存迁移与现场验证边界见[自动调速](../../../docs/adaptive-pacing.md)。
